# استراتيجية حدود الاستخدام (API Rate Limits Strategy)

لمعالجة مشاكل السقوط المفاجئ بسبب الحد المسموح للاستخدام (429 Rate Limit) في بيئة إنتاجية (Production) تم اتخاذ التدابير التالية في خوارزمية API (المرحلة **S3**):

## 1. طابور المهام (Queue Management)
لا يرسل التطبيق جميع أجزاء الصوت في نفس اللحظة (Fire & Forget)، بل ينتظر بصبر نتيجة الجزء الأول قبل رفع الذي يليه عبر لوب تكراري في `processing_provider.dart`.

## 2. Exponential Backoff & Retry
ضمن دالة `transcribeAudio` في `GroqApiService`:
- خصصنا `maxRetries = 4`.
- استخدمنا مكتبة `dart:math`، لاحتساب فترة التأخير `retryDelay = pow(2, currentTry).toInt() + 1`.
- يعطي النظام أوقات راحة متفاوتة للملقم: 3 ثوانٍ، 5 ثوانٍ، 9 ثوانٍ، ثم 17 ثانية. 
- يساهم التفاوت في تبريد سيرفرات API دون خسارة البيانات المرفوعة.

## 3. Cooldown System & 429 Status
عندما يلتقط النظام `statusCode == 429`:
- يعتبرها إشارة إلى ضرورة الإبطاء.
- يعتمد نفس مدة الـ Delay لعمل Pause مؤقت للالتزام بسياسات الـ API Provider الحرة، ثم يستكمل.
- في حال استنفاد كل المرات (4 محاولات)، يتم تنبيه المستخدم بشكل مباشر: `"تم تجاوز الحد المسموح به للطلبات. يرجى الانتظار قليلاً ثم المحاولة مرة أخرى."` دون انهيار واجهة التطبيق.
