# تقرير معالجة الأخطاء (Error Handling Report)

تم تنفيذ المرحلة **S5** الخاصة بتحسين رسائل الأخطاء ومعالجتها لمنع أي انقطاعات فجائية (Crashes).

## 1. أخطاء الإنترنت والشبكة
تمت معالجة الخطأ باستخدام `connectivity_plus` وفحص استجابات مكتبة `Dio` (الرزم من نوع `DioException`).
- **رسالة المستخدم:** `"انقطع الاتصال بالخادم. تأكد من استقرار شبكة الإنترنت وضعف التغطية."` بدلاً من المصطلحات التقنية المعقدة.
- يتم تطبيق **Retry** لعدة محاولات وإذا استمر الانقطاع يخبر المستخدم.

## 2. أخطاء التخويل والإذن المجاني (API)
- **Response 401:** تعني خطأ في المفتاح، الرسالة: `"مفتاح API غير صالح. يرجى التحقق من إعدادات المفتاح وتحديثه."`
- **Response 429:** تعني انتهاء الاستهلاك المجاني (Rate Limit) -> تمت معالجته باستخدام Backoff Cooldown (شُرح بالتفصيل بملف استراتيجية حدود الـ API).
- **Response 413:** الرسالة: `"حجم الملف كبير جداً وتجاوز قدرة التقسيم التلقائي."`

## 3. التعامل مع أخطاء الملف (Null Safety)
تم تطويق جميع مدخلات ومخرجات الملفات عبر `Null Safety` في Flutter 3+. لو تم اختيار ملف لم يعد موجوداً، سيبلغ التطبيق بتنبيه آمن ولن يفشل الـ `FFmpeg`.

## 4. التعافي وحفظ التقدم
تم تعديل نظام الخلفية (`Background Service`) لكي يدير طابور الأجزاء (Chunks). لو فشل أي جزء، يقوم النظام بإعادة المحاولة بمقدار $4$ مرات بأسلوب *Exponential Backoff*، مما يسمح بحل مشاكل تقطع الويفي أو الشبكة.
